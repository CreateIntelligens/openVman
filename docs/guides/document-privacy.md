# 文件去識別化與保留原則

本原則適用於版本庫文件、範例，以及實驗報告附帶的 JSON、JSONL、CSV 與 YAML。正式服務設定、資料庫及私有原始資料另行管理，不以編輯文件取代服務設定或憑證輪替。

## 文件使用示例值

| 資料 | 文件寫法 |
|---|---|
| 使用者與登入名稱 | `<username>`、`example-user` 或角色名稱；ROOT 以 `ROOT_USERNAME`／`AUTH_ROOT_USERNAME` 說明 |
| 帳號、專案、金鑰及請求識別碼 | `<account-id>`、`example-industrial-project`、`example-hospital-project`、`example-request-001`；不公開真實值 |
| 憑證與密碼 | 環境變數或 secret store；不記錄明文、真實 key ID、完整 token 或私人金鑰 |
| 自架網域與主機位址 | `api.example.com`、用途明確的 `*.example.com` 或文件專用 IP `192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24` |
| 個人路徑與聯絡資料 | `/path/to/openVman`、`/home/operator`、`operator@example.com` |
| 客戶或部署專案名稱 | 工業示範專案、醫院示範專案等別名；不記錄私人聯絡資料或個別商業條件 |

示例值必須換成部署環境自己的設定，不能直接拿示例專案 ID 呼叫正式服務。文件中的歷史測量仍代表原測量，替換識別資訊不表示曾對 `example.com` 執行測試。

保留 API 路徑、環境變數名稱、Docker service DNS、localhost、協定欄位與產品型號。官方第三方文件、模型／論文來源、公開套件與映像分發網址、著作權與授權署名，以及明確公開的供應商聯絡窗口，經確認後可保留。公開型錄的製造商名稱是來源事實，不能據此推論任何實際客戶關係。

## 哪些文件與 JSON 值得上版

| 類型 | 處理方式 |
|---|---|
| 現行 README、規格、操作手冊 | 保留並更新；同一主題維護同一份文件 |
| OpenSpec 變更規格 | 保留設計與驗收邊界，部署識別改成示例 |
| 凍結題庫、標準答案、來源快照 | 保留；是測試輸入及結果追溯依據 |
| 支撐有效實驗結論的回答、逐份評分與必要稽核 | 保留去識別化版本；保持結構、數字、題號與評分不變 |
| 可重建的筆記副本、評分輸入包、summary、中途 checkpoint | 依各實驗驗證入口決定最小保留集；可由已上版證據可靠重建者不重複提交 |
| 重複報告、被現行規格取代的早期任務草稿 | 刪除並修正引用；需要舊版本時查 Git 歷史 |
| 已退場實驗的巨量逐筆 dump、一次性 smoke 回應 | 刪除；保留必要摘要與環境，註明無法僅憑摘要重算逐筆結果 |

不能為了刪 JSON 而關閉驗證或把失敗標成通過。去識別化若改變附件 bytes，必須更新對應附件 checksum 並重跑驗證；未修改的原始型錄／產品內容雜湊保持不變。歷史分數不得因改了顯示文字而重新宣稱是新測量。

## 新增或修改文件時檢查

```bash
python3 scripts/check_document_privacy.py
python3 -m pytest tests/test_document_privacy.py -q
```

檢查器使用標準庫，從 Git 清單掃描追蹤及未忽略的新文件、範例 HTML 與指定實驗附件。偵測內網／實機 IP、MAC、常見帳號／專案／請求 ID、憑證格式、literal 登入名稱、個人 home path、未審查 email 與網址主機。輸出只有檔案、行號及分類，不回顯可能的祕密值；exit 0 為通過、1 為命中、2 為掃描失敗。Contracts CI 執行相同檢查。

新公開來源網址必須人工核對後才加入精確 host allowlist。檢查器不會自動辨識所有自然語言姓名、客戶關係、截圖、PDF、音訊或任意格式個資；提交前仍需人工看差異。被忽略的 runtime、私有資料、第三方授權檔及 Git 歷史不在檢查範圍，通過不代表整個儲存庫或歷史已完全匿名。
