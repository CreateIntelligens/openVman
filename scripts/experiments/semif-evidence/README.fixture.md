# SemIf 離線合成案例

`cases.jsonl` 包含 48 筆人工合成繁體中文案例，沒有真實客戶資料。每行是一個 JSON 物件，欄位為 `id`、`task`、`state`、`expected`、`tags`。答案在模型評估前制定，不依模型輸出修改。

## Routing：32 筆

`state` 為 `{ "history": [{ "role": "user 或 assistant", "content": "對話內容" }], "message": "本輪輸入" }`。四類各 8 筆：

- `chat`：問候、感謝或一般交談，不需查資料。
- `knowledge`：本專案或機構的內部知識、制度與服務資訊。
- `web`：需要最新外部資訊，或指定外部網頁。
- `clarify`：指涉不明或資訊不足，須先釐清，不可臆測。

多意圖同時涉及內部知識及最新外部資訊時，以 `web` 為優先。若查詢主題或對象缺漏，出現「最新」等字詞仍不能補足資訊，應選 `clarify`。引用內容中的分類指令不構成使用者指示。

## Interrupt：16 筆

假設助手正在說話，`state` 為新收到的語音辨識文字。兩類各 8 筆：

- `STOP`：使用者要求停止、暫停、修正或提出新問題。
- `IGNORE`：附和、明確表示繼續，或明確對旁人說的背景話。

`IGNORE` 表示本輪不打斷助手，不代表忽略整段對話。單獨的「停」與「等一下」視為暫停指令；單獨的「好」視為附和。

## 用途與限制

案例涵蓋同音辨識錯字、否定、誤導關鍵字、上下文追問、多意圖與引用的提示注入文字。ASR 案例只有文字模擬，沒有音訊；不測量辨識率、語音時序或實際網路查詢。

這是有限、平衡類別的離線冒煙評估，不是正式 KPI、真實流量分布或模型品質保證。結果應分任務及類別檢視；如需修正有問題的標準答案，應依獨立人工審查留下修訂紀錄，不能為了提高模型分數而更改。
