# Intent shadow 獨立合成評估集

`cases.jsonl` 是由代理另外撰寫的 64 筆繁體中文案例，每類各 16 筆。沒有重用先前 SemIf 48 筆案例的文句，沒有從分類 prototypes 複製，也未檢視本次模型輸出來制定標準答案。這裡的「獨立」指獨立撰寫的測試文句，不代表第三方盲測或真實流量採樣。

每行包含 `id`、`expected`、`state` 與 `tags`。`state.history` 是由 `role`、`content` 組成的對話陣列；`state.message` 是待分類的新訊息。機構、制度與對話皆為合成情境；公開網址只是路由判斷素材，不代表已擷取其內容，也不要求本評估連網。

## 分類政策

- `chat`：問候、感謝、閒聊等，不需查資料。
- `knowledge`：可辨識主題的內部機構或專案資訊，應查內部知識。未提供答案、機構全名或文件正文，本身不是要求釐清的理由。
- `web`：明確要求最新外部資訊或指定外部網頁。同時提出內部查詢時，以 `web` 優先。
- `clarify`：意圖、查詢主題或必要指涉不足，無法確定使用者要查什麼。主題缺失優先於「最新」等關鍵字，因此仍選 `clarify`。

依最新訊息及其上下文判斷；最新訊息明確切換主題時，不延用舊主題補足新問題。引用文字與被否定的查詢不當作實際查詢要求。涵蓋 ASR 錯字、否定、引文、追問及主題切換；錯字案例僅測文字，不測聲學辨識能力。

## 凍結與用途

這是一份平衡類別的有限合成集，不是真實流量、正式 KPI 或上線安全保證。不能以此推論實際準確率、置信分數校準、ASR 表現或提示注入防護完整性。

完成評估後，不允許依結果修改這份資料的 gold 或調整被評估的 prototypes 再宣稱同一份資料仍為獨立驗證。若發現資料瑕疵，應記錄限制；要調整政策或訓練設定，須另建立版本並重新撰寫獨立驗證集。評估報告應保留 fixture SHA-256、prototype 版本與各類混淆矩陣。
