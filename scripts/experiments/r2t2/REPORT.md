# Confucius4-R2T2 辨識實驗（2026-10-01）

目的：評估網易有道開源的 Confucius4-R2T2（Qwen3-ASR-1.7B）能不能取代或補充現有的 Breeze 批次辨識和 Gemini Live 串流辨識。

## 兩套部署

| | .35:8040 | .37:8803 |
|---|---|---|
| 程式 | `server.py`（Sanic + vLLM），systemd | `app/main.py`（FastAPI + transformers），容器，GB10 |
| 同時請求 | 同時送多句會卡住（實測 3 句後全部 60 秒回 503） | 同時請求會排隊，有串流 |
| 結論 | 接成獨立引擎 `r2t2-dev`／`r2t2-dev-live`，帳號選了才用，批次只等 20 秒 | 正式使用 |

## 方法

- 音檔：
  - 鶴記 10 題 × 4 種合成聲音：edge-tts 兩種清楚的聲音，加 VoxCPM 兩種帶口音的聲音。用的是 `scripts/voice_e2e/.cache` 裡的快取，要先跑過 voice_e2e 才有。
  - 台語連續劇真人錄音 75 句：`scripts/voice_e2e/cases/taigi-drama.json`。
- 每一句都測「帶專案詞表」和「不帶詞表」兩種：R2T2 把詞表放在 `context`（批次）或 `system_prompt`（串流），Breeze 放在 `prompt`。
- R2T2 輸出簡體，先轉成繁體才算錯字率（`app.utils.chinese.convert_to_traditional`，這也是正式整合時的做法）。
- 延遲：批次算「上傳到出字」；串流算「最後一個有聲音的取樣到定稿」。合成音檔結尾有長短不一的靜音，所以不從音檔結尾算。
- 腳本：
  - `run.py`：.35 批次，對照 Breeze。
  - `stream.py`：串流，可用 `--url` 指定部署、`--parallel` 指定同時幾路。
  - .37 批次測試沒有獨立腳本，結果在 `results_37*.json`。

## 結果：鶴記 10 題，清楚聲音（edge 兩種，20 句），帶詞表

| | 錯字率 | 專有名詞聽對 | 延遲 p50 |
|---|---|---|---|
| Breeze 批次（現行） | 5.8% | 14/18 | 約 1.0 秒 |
| R2T2 .37 批次 | 6.9% | 13/18 | 0.28 秒 |
| R2T2 .35 批次 | 8.1% | 13/18 | 1.2 秒 |
| Gemini Live 串流（現行；不吃詞表） | 17.6% | 3/18 | 2.05 秒 |
| R2T2 .37 串流，單路 | 6.9% | 13/18 | 1.10 秒 |
| R2T2 .37 串流，同時 3 路 | 6.9% | 13/18 | 1.59 秒，沒有漏掉斷句 |
| R2T2 .37 串流，經 openVman 轉接（`/api/v1/asr/stream`） | 6.9% | 13/18 | 1.17 秒 |

- 帶口音的 VoxCPM 聲音，帶詞表時：
  - 批次：R2T2 .37 錯字率 26.9%、專有名詞 11/18；Breeze 28.7%、8/18。
  - 串流：R2T2 .37 錯字率 26.9%、專有名詞 10/18。
- 不帶詞表時：R2T2 .37 批次專有名詞 8/18，Breeze 只有 1/18。R2T2 本身認識的專有名詞比較多。
- 台語真人 75 句：R2T2 會把台語寫成台語漢字（例如「恁這期」「阮」），對照華語字幕的錯字率 0.81；Breeze 翻成華語，錯字率 0.36。台語分流不能用 R2T2。

## 其他觀察

- .35 串流不指定語言時（`zhen` 會變成 None），帶口音的華語曾被轉成葡萄牙文。.37 改版後預設以中文解碼。
- .35 串流帶熱詞時，偶爾會吃掉句尾（例如「沉水泵最深可以放多深」變成「沉水泵最多」）。.37 改版後，斷句時回傳整句重新辨識的 `final_text`，沒有再重現。
- 簡轉繁會把「著」轉成異體字「着」（例如「自動着脫裝置」）。這是共用轉換工具既有的行為，小米也一樣。

## 結論

- 串流：R2T2 .37 比 Gemini Live 準很多（專有名詞 13/18 對 3/18），定稿也快將近一秒，已接成前台引擎 `r2t2-live`。
- 批次：R2T2 .37 準確度和 Breeze 相當、快約 3 倍，已接成可選的批次引擎 `r2t2`。要不要改成預設，等真人華語錄音測過再決定。
- 以上都是合成語音。真人的口音、收音和環境噪音，都還沒驗證。

## 2026-10-05 複測：多語言與 Gemini 3.5

腳本與逐句結果在 `multilang/`：`r2t2_lang.py 37|35`（R2T2 串流，三種 language 設定）、`gemini_lang.py`（Gemini 串流）、`heji_terms.py`（鶴記型號題三家同時比）、`parallel_35.py N`（.35 同時 N 路）、`e2e_stream.py`（經過 backend，要先把測試帳號偏好設成要測的串流引擎）、`taigi_stream.py`（台語）。都直接連引擎，一次一路，不經過帳號偏好。Gemini 用部署設定的 `gemini-3.5-transcribe-live`。

### 這次的結論

- 要型號準：R2T2 .37 ＋詞表，但要先知道語言。
- 要自動判斷語言：Gemini 3.5 最穩；.35 `zhen` 能分中英西，句尾被吃掉的問題還在，同時多路會排隊變慢。
- 台語只能走 Breeze。沒開台語分流的專案用 .35 `zhen` 時，講台語會出英文或葡萄牙文亂碼。
- 以上除台語外都是合成語音，不是真人。
